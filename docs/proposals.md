# 追加機能の提案

依頼の必須項目に加え、LEO サービスの特性理解に有用と考えられる機能案です。
（本リポジトリには「基盤 + 実装済み機能」を収め、以下は今後の拡張候補）

## 実装済み（基盤に含む）
- SINR × スループット/RTT/ジッタ の**時系列対比**と時間窓での自動突き合わせ。
- **障害物率(Starlink)**・端末遅延の記録 → 品質劣化が電波要因か経路要因かの切り分け。
- ハンドオーバー**先読み**（次の切替まで何秒か）。

## 提案（優先度高)
1. **ハンドオーバーと品質劣化の相関分析**
   予測ハンドオーバー時刻の前後で RTT/ロス/ジッタがどう変化したかを自動集計。
   「切替のたびに ○ ms スパイク」といった特性を定量化。
2. **片道遅延(OWD)・上り下り個別ジッタ**
   受信 PC を NTP/PTP 同期し、上り/下りの遅延非対称性を可視化（`owd_ms` は器あり）。
3. **アラート/通知**
   SINR 低下・ロス急増・障害物率上昇・予測ハンドオーバー直前に Slack/メール通知。
4. **CSV/Prometheus エクスポート**
   既存監視基盤(Grafana 等)への連携。`Storage` 差し替えで対応可能。

## 提案（中）
5. **スカイプロット/カバレッジ表示**
   可視衛星を方位-仰角の極座標で描画し、アンテナ実測の向き(RF)と重ねて健全性確認。
6. **MTU/輻輳・バースト特性測定**
   パケットサイズ別スループット、二重化(Starlink+OneWeb)時のフェイルオーバー時間。
7. **DNS/アプリ体感指標**
   代表的エンドポイントへの HTTP 取得時間・DNS 解決時間で「体感」を補足。
8. **天候・降雨との相関**
   気象 API を取り込み、降雨減衰(特に Ka/Ku)と SINR の関係を分析。

## 提案（運用）
9. **複数拠点集約**
   各拠点の sender/collector から中央 Storage へ集約し、拠点横断比較。
10. **測定スケジューラ**
    高頻度測定が回線を圧迫するため、時間帯・トラフィック連動で測定強度を調整。
