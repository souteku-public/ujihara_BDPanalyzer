# 受信拠点ルータ設定 (富士通 Si-R G210 / NURO Biz 固定IP)

「全通過」状態から、**本アプリに必要な最小限だけを通し、それ以外を遮断する**
設定方針をまとめる。Si-R G210 は富士通 Si-R シリーズの IP アクセスルータで、
NURO Biz では標準貸与機。設定は Web GUI またはコンソール (CLI) から行う
(NURO Biz の貸与条件によっては設定変更をサポート経由で依頼する運用の場合が
あるため、事前に契約内容を確認すること)。

> 前提の記号 (実環境の値に読み替える):
> - `<固定グローバルIP>` : NURO Biz で割り当てられた固定 IP
> - `192.168.1.0/24`     : LAN セグメント (実際の設定に合わせる)
> - `192.168.1.10`       : 受信 PC (本アプリの receiver) の LAN 内 IP — **DHCP 予約か静的設定で固定すること**
> - `<送信拠点IP>`       : 衛星側 (送信側) 拠点のグローバル IP

---

## 1. 設計方針 (何を通し、何を止めるか)

### インターネット → LAN (着信) — 必要なのは 2 つだけ

| # | プロトコル/ポート | 転送先 | 用途 | 送信元制限 |
|---|---|---|---|---|
| 1 | TCP 5301 | 192.168.1.10:5301 | 測定の制御・スループット | 可能なら `<送信拠点IP>/32` に限定 |
| 2 | UDP 5302 | 192.168.1.10:5302 | RTT/ジッタ/ロス・負荷試験 | 同上 |

**上記以外の着信はすべて遮断**(デフォルト拒否)。特に:
- **TCP 8080 (ダッシュボード) は絶対に公開しない**(認証なしの管理画面のため。閲覧は LAN 内から、遠隔で見たい場合は VPN 経由にする)
- ルータ自身の管理画面 (HTTP/HTTPS/telnet/SSH) への WAN 側からのアクセスを禁止

送信元制限の考え方:
- **OneWeb (固定 IP) 側が送信拠点** → `/32` でピンポイント許可(最良)
- **Starlink 側が送信拠点** → CGNAT の出口 IP は変動し得るため `/32` 固定は不可。
  (a) ルータでは宛先ポートのみで許可し、**アプリ側の `allowed_sources`
  (下記 §4) で広めの CIDR を指定**して二段で絞る、
  (b) 実運用の出口 IP をダッシュボードの「グローバルIP取得」で確認し、
  変わったらフィルタを更新する、のいずれかで対応

### LAN → インターネット (発信) — アプリが使うもの

| 用途 | プロトコル/ポート | 宛先 |
|---|---|---|
| TLE 取得 (CelesTrak) / 気象 (Open-Meteo) / グローバルIP確認 | TCP 443 | any |
| DNS | UDP/TCP 53 | 契約 DNS |
| 時刻同期 (NTP) — 測定の時刻整合に重要 | UDP 123 | NTP サーバ |
| この拠点からも能動測定する場合 | TCP 5301 / UDP 5302 | 対向拠点 |

発信は「全許可」でも動くが、測定専用セグメントなら上記+OS更新程度に絞ると堅い。

## 2. Si-R G210 設定例 (CLI)

> Si-R シリーズのコマンド体系はファームウェア版数で細部が異なる。
> **投入前に必ず該当版のコマンドリファレンス(富士通公開)で構文を確認**し、
> Web GUI で設定する場合は §1 の表を「ポートマッピング」「パケットフィルタ」
> 画面に読み替えて入力する。以下は考え方を示す設定例。

```text
# ===== 静的 NAPT (ポートマッピング): 必要な 2 つだけ =====
# TCP 5301 → 受信 PC
lan 1 ip nat static 0 192.168.1.10 5301 <固定グローバルIP> 5301 6
# UDP 5302 → 受信 PC
lan 1 ip nat static 1 192.168.1.10 5302 <固定グローバルIP> 5302 17

# ===== ACL 定義 =====
# 測定ポート宛の着信 (送信元を絞れる場合は any を <送信拠点IP>/32 に)
acl 0 ip any <固定グローバルIP>/32 6 any
acl 0 tcp any 5301
acl 1 ip any <固定グローバルIP>/32 17 any
acl 1 udp any 5302
# 戻りパケット (LAN 発の通信の応答) は NAT/ステートフルで戻る構成が基本。
# ステートレス運用の場合は established 相当の戻り許可 ACL を追加する。

# ===== WAN 側 (lan 1) 着信フィルタ: 許可 2 本 + 全拒否 =====
lan 1 ip filter 0 pass acl 0 in
lan 1 ip filter 1 pass acl 1 in
# ルータ管理系への着信を明示拒否 (全拒否の前に置き、ログで観測する場合)
#   telnet(23)/http(80)/https(443)/ssh(22) 宛 → reject
lan 1 ip filter 99 reject any in log

# ===== 管理プレーンの保護 =====
# WAN 側からの装置管理を無効化し、LAN 内の管理端末のみに限定
#   (該当コマンド: serverinfo / remote 管理系。GUI では「装置アクセス制限」)
# - HTTP/telnet 管理: LAN 側のみ・可能なら管理端末 IP を限定
# - 管理パスワードを初期値から変更 (admin パスワード)
# - 使わないサービス (UPnP, リモート保守用ポート) を無効化
# - syslog / フィルタログを有効化し、拒否ログを確認できるようにする
# - 時刻同期 (SNTP) を有効化 (ログの時刻整合)

save
reset
```

### Web GUI で設定する場合の対応表

| GUI メニュー (名称は版数で多少異なる) | 入れる内容 |
|---|---|
| ポートマッピング / 静的NAT | §1 の着信 2 行 (TCP5301, UDP5302 → 192.168.1.10) |
| パケットフィルタ (WAN→LAN) | 上記 2 行を「許可」、最後に「すべて拒否」 |
| 装置アクセス (管理) | WAN 側管理オフ、管理パスワード変更、管理元 IP 限定 |
| UPnP | 無効 |
| ログ | フィルタ拒否ログ + syslog 有効 |

## 3. 受信 PC (Windows) 側の設定

- Windows Defender ファイアウォールで **受信規則: TCP 5301 / UDP 5302 のみ許可**
  (アプリ初回起動時の許可ダイアログで「許可」でも可)
- ダッシュボード (8080) はルータで転送しない限り外部から到達しないが、
  LAN 内にも見せたくない場合は `config.yaml` の `webapp.host` を
  `"127.0.0.1"` に変更 (そのPCのブラウザからのみ閲覧可能になる)
- PC の IP を固定 (ルータの DHCP 予約推奨) — ポートマッピングの転送先が
  変わらないようにする

## 4. アプリ側の送信元制限 (多層防御)

受信ポートは認証を持たないため、ルータと**アプリの二段**で送信元を制限する:

```yaml
# config.yaml (受信拠点側)
netqual:
  allowed_sources:
    - "203.0.113.10/32"      # OneWeb 側送信拠点 (固定 IP)
    # Starlink 側は出口 IP が変動し得るため、確認した IP/レンジを登録し
    # 変わったら更新する (リスト外からは TCP 即切断・UDP 無応答)
```

単体起動の receiver なら: `python -m bdp_analyzer receiver --allow 203.0.113.10/32`

## 5. 設定後の確認手順

1. 送信拠点から `python -m bdp_analyzer sender <固定グローバルIP>` → 数値が返る
2. 無関係の回線 (スマホテザリング等) から同コマンド → **タイムアウトする**
   (送信元制限が効いている証拠)
3. 外部ポートスキャン系サービスで 5301/5302 以外が閉じていることを確認
4. ルータの拒否ログに不審な着信が落ちていることを確認

## 6. 残存リスクと運用メモ

- 測定ポートを開けている以上、許可送信元がスプーフィングされた UDP は届き得る
  (エコー応答は等量なので増幅には使われない)。TCP 側はハンドシェイクが必要な
  ため送信元詐称は実質不可
- 5301/5302 は well-known ではないためスキャンで狙われにくいが、
  変更したい場合は config の `control_port` / `udp_port` とルータ設定を
  合わせて任意のポートに変更可能
- ルータのファームウェアは NURO Biz の保守ポリシーに従い最新を維持
